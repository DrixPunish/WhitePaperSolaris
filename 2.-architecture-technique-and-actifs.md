# 2. Architecture Technique & Actifs

**2.1. La Blockchain : Solana**

* **Choix :** **Solana** est la blockchain idéale pour ce projet pour plusieurs raisons :
  * **Frais extrêmement bas :** Les transactions coûtent une fraction de centime, ce qui rend possible, si nous le souhaitons à l'avenir, de tokeniser davantage d'éléments sans pénaliser les joueurs. Surtout, cela rend l'expérience utilisateur fluide et agréable.
  * **Haute rapidité :** Solana peut traiter des milliers de transactions par seconde, évitant ainsi les congestions et les ralentissements, même avec une base de joueurs importante.
  * **Modèle "Compte" :** Le modèle de compte de Solana est plus flexible que l'EVM, ce qui facilite la gestion d'états complexes et la interaction entre programmes (smart contracts).
  * **Croissance de l'écosystème gaming :** Solana attire de nombreux projets gaming (Star Atlas, Aurory), ce qui crée un écosystème dynamique et des opportunités de collaboration.
* **Actifs On-Chain (Solana) :**
  * **Le Jeton :** Implémenté via le programme Token (norme SPL - Solana Program Library), l'équivalent du ERC-20 sur Ethereum.
  * **Les NFT de Planètes :** Utiliseront la métaplex standard (via le programme Token Metadata), qui est la norme la plus répandue pour les NFT sur Solana. Cela garantit une compatibilité immédiate avec les principaux marketplaces (Magic Eden, Tensor) si nous souhaitons étendre le marché au-delà de notre application.
  * **Les NFT de Bons Impériaux :** Également basés sur le standard Metaplex.
* **Actifs Off-Chain :** Inchangé. Les données de jeu (flottes, bâtiments, ressources) restent sur un serveur centralisé pour des raisons de performance et de coût. L'état on-chain (possession des planètes, solde de jetons) sert de "source de vérité" pour les actifs ayant une valeur économique réelle.
